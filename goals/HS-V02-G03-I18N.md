# HS-V02-G03 — Internationalization

## Status

PLANNED after accepted G02.

## Objective

Complete the TabBeacon-compatible Human localization architecture for `en-US` and `zh-CN`, including runtime switching and a safe persistent user preference, without localizing machine contracts.

## Scope

- Complete typed catalog coverage for every Reliability Center view, state, overlay, footer, Human report, and Human diagnostic introduced through G02.
- Support `auto`, `en-US`, and `zh-CN` with the resolution order defined in `I18N_DESIGN.md`.
- Implement immediate in-memory language switching from Settings.
- Persist the preference only after explicit Apply in HookStat-owned user-local `interface.toml`.
- Make absent-file reads non-mutating; preserve unknown fields; atomically write; refuse stale/concurrent Apply.
- Use CJK/grapheme-aware display width and test normal/narrow/minimum layouts.
- Support auto/always/never color policy while retaining textual/glyph state in no-color mode.
- Prove JSON, stable plain keys, database values, IDs, and commands remain locale-independent.

## Non-goals

- Do not translate raw machine IDs, CLI commands/flags, JSON fields, receipt fields, schema values, runtime IDs, handler keys, revisions, or user annotations.
- Do not add more locales in v0.2.
- Do not store preferences in the repository or Codex configuration.
- Do not change instrumentation, trust, receipts, proxy behavior, or the reliability ledger.
- Do not add a large localization dependency without a separately justified decision.

## Acceptance criteria

```text
LOCALES=en-US,zh-CN
AUTO_LANGUAGE=true
TYPED_TRANSLATION_KEYS=true
HARDCODED_UI_STRINGS=false
RUNTIME_LANGUAGE_SWITCH=PASS
PERSISTENT_PREFERENCE=PASS
ABSENT_PREFS_READ_NON_MUTATING=true
CONCURRENT_PREFS_CHANGE_REFUSED=true
FALLBACK_LOCALE=en-US
CATALOG_PARITY=PASS
CJK_WIDTH=PASS
ZH_CN_TUI=PASS
EN_US_TUI=PASS
NO_COLOR_SEMANTICS=PASS
MACHINE_CONTRACT_LOCALE_INDEPENDENT=true
PROJECT_LOCAL_PREFERENCES=false
```
